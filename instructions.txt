Instrucciones para IA de Codificación —
Aplicación Web Dashboard Metro Chile
1. Rol que debe asumir la IA de desarrollo
Asume el rol de un desarrollador de software senior , arquitecto de software e ingeniero de software
experto en aplicaciones web, APIs, sistemas modulares, integración de dispositivos IoT/visión
computacional y dashboards operacionales para clientes industriales.
Debes desarrollar una aplicación web modular , mantenible y preparada para integración con
dispositivos externos desarrollados por otro equipo. El objetivo principal es construir un dashboard web
que reciba, procese, almacene, visualice y exporte datos provenientes de dos tipos de dispositivos de
visión computacional utilizados en un proyecto piloto para Metro de Chile.
La solución debe estar diseñada con buenas prácticas de ingeniería, separación clara de
responsabilidades, documentación interna y facilidad de integración futura.
2. Contexto del proyecto
El cliente es la empresa Metro de Chile.
El sistema forma parte de un piloto tecnológico orientado a seguridad operacional y prevención de
riesgos en frentes de trabajo. Los dispositivos de visión computacional serán desarrollados por otros
miembros del equipo, por lo tanto, esta aplicación web debe estar preparada para recibir los datos
cuando dichos dispositivos estén listos.
La aplicación web no controla directamente los dispositivos. Su responsabilidad es:
Recibir datos enviados por los dispositivos o por el gateway/intermediario.
Validar los JSON entrantes.
Normalizar la información.
Almacenar datos históricos.
Mostrar métricas en un dashboard.
Permitir descarga manual de la información en formato tabular .
Aislar todos los parámetros de integración para facilitar cambios futuros.

Propósito operacional
El dispositivo de detección de EPP tiene como finalidad cuantificar el correcto uso de equipos de
protección personal por parte de los trabajadores.

durante un tiempo, por lo que no se debe asumir que cada JSON representa necesariamente un

mezclar ambos sin control.

10. Principio clave de arquitectura: desacoplamiento de
integración
Debido a que los dispositivos son desarrollados por otro equipo, la aplicación debe aislar todas las
variables de integración en una carpeta específica.
Debe existir una carpeta llamada:
backend/app/integration_config/
Esta carpeta debe contener todos los archivos relacionados con:
Nombres de campos esperados.
Versiones de esquemas.
Mapeo de campos externos a campos internos.
IDs de dispositivos autorizados.
Tipos de dispositivos.
Parámetros de validación.
Umbrales de severidad.
Configuración de gateway.
Configuración de endpoints externos, si aplica.
El objetivo es que, cuando el equipo de dispositivos entregue el JSON final, solo sea necesario modificar
archivos dentro de esta carpeta y, como máximo, los schemas/normalizers asociados.
No se debe dispersar la lógica de integración por todo el backend.
